# WooCommerce-file-sender
## Описание 
Данный скрип был написан для автоматизации рассылки файлов по заказам из WooCommerce.
Необходимость возникла при понимании, что не все пользователи в состоянии самостоятельно скачать файлы по генерируемым ссылкам.

Скрипт собирает заказы со статусом `processing` и рассылает письма с файлами. 

По выполнению приходит отчет в телеграм.

## Настройка и выполнение

Работоспособноть проверена на Python 3.8+. 
Установка зависимостей `pip install -r requirements.txt`

Для работы необходимо наличие .env файла:
```
TELEGRAM_BOT_TOKEN=
TELEGRAM_USERS_ID=[""]
WC_USER_KEY=
WC_SECRET_KEY=
WC_URL=
EMAIL_SENDER=
EMAIL_PASSWORD=
EMAIL_DISPLAY_NAME=
EMAIL_SMTP_SERVER=smtp.yandex.ru
EMAIL_SMTP_PORT=465
EMAIL_SMTP_LOGIN=
```

`EMAIL_SMTP_LOGIN` — необязательный логин для SMTP-авторизации. Если он не задан
или пустой, используется `EMAIL_SENDER`, как в текущей настройке Яндекса.
`EMAIL_SENDER` задаёт адрес отправителя, а `EMAIL_DISPLAY_NAME` — его имя.

### Отправка через Selectel

Укажите SMTP-реквизиты из панели управления Selectel:

```dotenv
EMAIL_SENDER=sender@example.com
EMAIL_DISPLAY_NAME=Название магазина
EMAIL_SMTP_LOGIN=selectel-login
EMAIL_PASSWORD=selectel-password
EMAIL_SMTP_SERVER=smtp.mail.selcloud.ru
EMAIL_SMTP_PORT=1127
```

Адрес отправителя должен принадлежать домену, подключённому к почтовому сервису
Selectel со статусом `Verified`. Используется SSL на порту `1127`; подключение
через STARTTLS на порту `1126` не поддерживается. Устанавливать sSMTP не нужно:
приложение подключается к SMTP-серверу напрямую.

### Проверка

Для проверки SMTP-настроек задайте получателя в `.env`:

```dotenv
TEST_EMAIL=your-address@example.com
```

Отправьте тестовое письмо:

```sh
python send_test_email.py
```

Можно разово указать другой адрес:

```sh
python send_test_email.py other-address@example.com
```

Скрипт использует те же `EMAIL_*` настройки и SSL, что и основная рассылка.
Для него нужны только почтовые настройки, без WooCommerce и Telegram.
Код завершения `0` означает, что SMTP-сервер принял письмо; `1` — ошибку настройки
или отправки. Результат выводится в консоль. Проверьте папки входящих и спама.

Тесты подменяют SMTP-соединение и не отправляют реальные письма:

```sh
python -m unittest discover -s tests -v
```

### Запуск

Логи выводятся в консоль с датой, временем и уровнем сообщения. В них видны
количество загруженных заказов, подготовка файлов и купона, отправка каждого
письма (включая части), смена статуса заказа и итоговые счётчики. Ошибки содержат
контекст заказа и traceback. Если SMTP принял письмо, это отмечается отдельно
от успешного изменения статуса заказа; при ошибке обработки продолжается
обработка следующих заказов.

В Telegram отправляются этапы уровня `INFO` и выше: загрузка заказов, подготовка
и отправка каждой части письма, подключение и авторизация SMTP, попытки передачи,
ответы сервера и смена статуса заказа. Сообщения `DEBUG` и диагностика самого
Telegram-транспорта остаются в консоли.

У каждого запуска есть идентификатор; в логах также указан PID процесса. По ним
можно различать повторные и одновременно работающие запуски. Итоговый отчёт
содержит результаты частей письма, причины ошибок и отдельные счётчики успешных
и неуспешных заказов. Приём SMTP-сервером не означает доставку во входящие.

Длинные уведомления, включая traceback, делятся на последовательные сообщения.
SMTP-пароль и токен Telegram скрываются в выводе; SMTP-команды AUTH и содержимое
писем не логируются. Число попыток отправки и задержки yagmail сохранены.

Для сохранения логов при запуске из cron перенаправьте вывод:

```sh
python main.py >> sender.log 2>&1
```

Для выполнения скрипта использовал cron:
```
*/30 * * * * cd /home/Woo-sender/ && /home/Woo-sender/env/bin/python /home/Woo-sender/main.py
```
